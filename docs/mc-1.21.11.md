# Horizon for Minecraft 1.21.11

Horizon targets Minecraft 26.3. This page is the state of the work to also build it for 1.21.11, the last
release before 26.1. **The 1.21.11 build compiles and its data prepares, but no harness has passed against vanilla 1.21.11 yet** (see 2a).
`cargo build -p horizon-client --features mc-1-21-11` selects it; the default build is still 26.3.

## Done and checked

- **Version facts.** `crates/horizon-core/src/version_1_21_11.rs` is generated by `tools/gen_version_consts.py`
  from the real 1.21.11 client jar (protocol 774, data version 4671, resource pack 75.0, data pack 94.1, Java 21).
- **Remapping.** 1.21.11 is the last obfuscated release. `crates/horizon-prepare/src/remap.rs` (also
  `horizon-prepare remap --mappings client.txt IN.jar OUT.jar`, and run by `horizon-prepare`/`tools/lab.py prepare`
  for any release whose version JSON has `*_mappings`) gives its jars Mojang's names. On the 1.21.11 client jar all
  10,291 classes, 45,679 fields and 89,557 methods of the mapping appear in the result under the right name and
  descriptor, 9,689 classes load (the other 602 only miss third-party libraries), and 1,715 sampled classes disassemble
  the same as the output of `tools/remap/Remap.java`, an independent ASM-based remapper.
- **Packet ids.** `crates/horizon-protocol/src/ids_1_21_11.rs` is `tools/generate_packet_ids.py`'s output for 1.21.11.
  It was first derived from the decompiled client (`tools/packets_from_sources.py`) and is identical to the packets
  report Mojang's own data generator writes from the 1.21.11 server jar.
- **What 26.1 to 26.3 changed in the packet set** (the rest is the same ids in the same order): clientbound play gains
  `add_transient_block`, `game_rule_values`, `low_disk_space_warning`, `post_effects`, `swing_animation`; configuration
  gains `post_effects`; serverbound play gains `attack`, `punch`, `set_game_rule`, `spectator_action` and loses `swing`.
- **Code that differs, handled behind `mc-1-21-11`:** the packet enums, `Interact` (1.21.11 has `interact`, `attack`
  and `interact_at` as actions of one packet; `play::attack_entity`, `play::swing_main_hand` and `play::interact_entity`
  send the right packets for either version), swings (`Animate` actions 0 and 3 in 1.21.11, `swing_animation` in
  26.3, `play::animate` holds the renumbered actions), game rules (`/gamerule` instead of `set_game_rule`),
  the `post_effects` sends. Tests that state packet ids as bytes know both numberings.
- **Launcher.** It lists, installs, updates and plays builds of both versions: a 1.21.11 build is a release tagged
  `mc1.21.11-v0.2.N`; each version updates only against its own installed builds (`a_1_21_11_build_is_its_own_line`),
  and the Versions page has a Minecraft 26.3 / Minecraft 1.21.11 switch. An installed build's Minecraft version and
  Java come from its own `research-lock.json`.

## Not done, in the order it blocks

1. **The pin: done.** `research-lock.1.21.11.json` matches the real version JSON (its sha1 is the `manifest_sha1`;
   client and server jar sha1s agree with it). The mapping files Mojang publishes have LF line ends: a copy saved with
   CRLF and no final newline has to be turned back (`tr -d '\r'`, then add the last `\n`) before its sha1 matches.
2. **`tools/lab.py prepare` for 1.21.11 runs end to end** (remapped client and server jars, inventories). It needs the
   launcher's `libraries/` and `assets/`; without them, `HORIZON_ALLOW_MISSING_CLIENT_LIBRARIES=1` lets it go on with
   the server side only. `tools/test_rust_parity.py` hands harnesses the remapped jars (the originals are still
   what is checked against the lock). **None of the 281 harnesses has passed against 1.21.11 yet: see 2a.**
2a. **The Java oracles are written against 26.3's classes.** `tools/oracle_compile_check.py` compiles them all
   against the prepared 1.21.11 jars: 128 of 308 files compile; the rest do not, because 26.1 to 26.3 changed vanilla's
   own API, not only its behaviour. The first harness tried (`food`) already stops at `new ServerLevel(...)`, which
   has an extra `RandomSequences` argument in 1.21.11. What is missing in 1.21.11, by number of errors: the
   density-function package layout (`levelgen.densityfunction`, `DensitySampler`, `NoiseStack`, material rules), the HUD
   and GUI extraction classes (`Hud`, `GuiGraphicsExtractor`), the render pipeline and model packages
   (`RenderPipeline`, `Material*`, `BlockStateModel*`, `ItemStackTemplate`), world clocks (`net.minecraft.world.clock`),
   data component initializers, entity-type and world-registry holders, `ContainerInput`, `SwingState`. Each is a
   subsystem the Rust code ports in 26.3's shape and 1.21.11 has in another (older) one, so the Rust side differs too,
   not just the oracle: that is the real size of "exactly 1.21.11". Client-side files also report errors about missing
   client libraries in a sandbox; read those as unknown.
3. **Packet layouts.** Only which packets exist and their ids are checked. Whether each shared packet has the same
   fields in 1.21.11 as the Rust code (written against 26.3) has not been compared: `VanillaPacketCodecOracle` and
   `tools/test_dedicated_server_parity.py` do exactly that once item 2 is done. The two layouts found by hand so far
   are `Interact` and `Animate`.
4. **Saves.** `datafix/files.rs` ports 26.1's `FileFixerUpper` (DataVersion 4772 on) and the 26.x file layout
   (`data/minecraft/...`); 1.21.11 has neither. A 1.21.11 build has to write the 1.21.11 layout and refuse worlds newer
   than 4671. `CURRENT` follows `DATA_VERSION`, so the fixer chain itself stops at 4671.
5. **26.1 to 26.3 behaviour in hand-written Rust** (mobs, block behaviour, commands, HUD, rendering, the registry list
   that includes `swing_animation` in `packets/play.rs`, spear and swing animations). Find it by running the harnesses
   against the 1.21.11 jars, then gate or remove each difference.
6. **Places that still say 26.3.** `launcher/src/browser.rs` `GAME` (mod browser compatibility), the launcher's Servers
   page (`servers.rs`, `servers_page.rs`: hosting a server from the launcher is 26.3 only), `crates/horizon-friends/src/wire.rs`
   (join messages carry the game version), mod manifests' `game` field, the README.
7. **CI and releases.** The workflows build one version. A second needs a build with `--features
   horizon-client/mc-1-21-11` and the 1.21.11 `research-lock.json`, published as `mc1.21.11-vX.Y.Z` with the same
   signed checksums. Nightlies of the second version are not handled by the launcher.
8. **Java.** Preparation still runs Mojang's own data generator and Horizon's Java exporters (Java 21 for 1.21.11);
   the game and the remapper are Rust.
